# Исследование разбора библиографических ссылок

НИР «Автоматизированная информационная система оформления библиографических ссылок».

Исследовательский вопрос: насколько точно правила, GROBID, AnyStyle и Qwen3-8B разбирают русскоязычные библиографические ссылки на 17 полей и позволяют оформлять их по ГОСТ Р 7.0.108–2022 и ГОСТ Р 7.0.5–2008?

## Данные эксперимента

[Dataset.xlsx](Dataset.xlsx) — предоставленный автором и исправленный человеком датасет от 31.10.2026. Файл используется без изменения байтов; его контрольная сумма хранится в [Dataset.sha256](Dataset.sha256).

- 490 записей: 396 из журнальных списков, 54 из ВКР, 40 из диссертации.
- DEV — 90, TEST — 400; 203 группы источников, без пересечения между частями.
- Профили: 207 по ГОСТ Р 7.0.108–2022 и 283 по ГОСТ Р 7.0.5–2008.
- Два листа: «Датасет» с 27 столбцами и «Источники» с происхождением записей. Неоднозначных полей в этой версии нет; знаменатели полного совпадения — 90 DEV и 400 TEST.
- SHA-256: `b18b1e2d3d7ab35744874a095fd50fad4cbeecfdd497ef6d1a7fcbc020ccc657`.

Эталон и контекст не передаются методам. Данные зафиксированы для этого эксперимента; программа не исправляет Excel. Проверка человеком сообщена автором и не превращается автоматически в числовую оценку согласия разметчиков.

## Один запуск четырёх методов

Установите [GROBID/Ollama](docs/PARSERS.md) и [AnyStyle](docs/ANYSTYLE.md). Для сводки нужен Python 3.9+ со стандартной библиотекой. Затем:

```sh
cd backend
./mvnw verify
cd ..
bash scripts/run-experiment.sh
```

Сценарий проверяет SHA-256 и среду, выполняет полный DEV, сохраняет протокол с неизменёнными настройками, обрабатывает полный TEST, рассчитывает метрики, оформляет ссылки и готовит бланк предметной проверки. Автоматической настройки методов между DEV и TEST нет. Всего 1960 извлечений: 360 DEV и 1600 TEST.

В другом терминале:

```sh
bash scripts/watch-test-progress.sh
```

При запуске на macOS сценарии удерживают компьютер от сна; крышку ноутбука следует оставить открытой. Новые папки не перезаписываются, ошибки методов сохраняются. Основные результаты: `research-runs/test-four-methods/evaluation/`, длительности и таблицы для статьи: `research-runs/test-four-methods/article/`, предметная проверка: `research-runs/test-four-methods/quality/`. Рабочие результаты исключены из Git.

Один процесс автоматически даёт precision/recall, micro/macro F1, F1 по полям, полные совпадения, лишние/конфликтующие поля и длительности. Для доли корректного оформления и неподтверждённых добавлений LLM необходимо заполнить решения проверки новых ответов. Эти показатели остаются неопределёнными, пока проверка не завершена. Согласие разметчиков требует отдельной процедуры и не вычисляется запуском моделей.

[Порядок опыта](docs/EXPERIMENTS.md), [данные](docs/DATASET.md), [оценщик](docs/EVALUATION.md), [форматтер](docs/FORMATTING.md), [предметная проверка](docs/QUALITY_REVIEW.md), [карта показателей статьи](docs/ARTICLE_METRICS.md).

Разбиение не заявляется независимо сформированным слепым holdout: корпус использовался при развитии методов. Результаты характеризуют фиксированный набор и выбранный краткий профиль оформления.

## Веб-сервис

Приложение: React 19 + TypeScript + Vite, Java 17 + Spring Boot 3.5, Spring Data JPA/Hibernate, PostgreSQL и Flyway. Сервер реализован полностью на Java.

Две вкладки: ручное оформление одной ссылки по рабочему профилю ГОСТ Р 7.0.5–2008 и импорт DOI/ISBN через Crossref/Open Library. Восемь типов источников, включая диссертацию и автореферат. Неполные метаданные отмечаются для исправления; отсутствующие реквизиты не выдумываются. Интерфейс поддерживает обычный режим и `/?embedded=1`.

### Запуск через Docker

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env, например значением из openssl rand -hex 32.
docker compose up --build -d
```

Откройте http://localhost:8080. Сервер автоматически применяет SQL-миграции Flyway и загружает стартовые правила только при их отсутствии.

### Локальная разработка

Нужны JDK 17+, Node.js 24 и PostgreSQL. Maven устанавливать отдельно не требуется: в `backend/` есть Maven Wrapper для macOS/Linux и Windows.

В первом терминале:

```sh
cd backend
export POSTGRES_HOST=localhost POSTGRES_DB=bibliography POSTGRES_USER=bibliography
export POSTGRES_PASSWORD='ваш-пароль'
./mvnw spring-boot:run
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api/` на Java-сервер `127.0.0.1:8000`.

### Проверки

```sh
cd backend
./mvnw verify
```

Тесты используют отдельный настоящий PostgreSQL 17, запускаемый тестовой библиотекой без Docker. При первом запуске Maven загружает зависимости и бинарные файлы PostgreSQL. Для внешней **тестовой** БД задайте `TEST_DATABASE_URL` (JDBC URL), `TEST_DATABASE_USER` и `TEST_DATABASE_PASSWORD`. Не указывайте рабочую БД: тесты меняют тестовые записи.

```sh
cd frontend
npm ci
npm run build
```

Описание [API](docs/API.md), [развёртывания](docs/DEPLOYMENT.md), [возможностей сервиса](docs/FEATURES.md), [фактических проверок](docs/VALIDATION.md).

В веб-интерфейсе импорт eLIBRARY/EDN и произвольного URL, пакетный разбор списков, дополнительные стили, сохранение списков и LDAP пока не реализованы. Исследовательский пакетный разбор доступен через CLI. Проверка исследовательских результатов не является аттестацией всех шаблонов ручной веб-формы.

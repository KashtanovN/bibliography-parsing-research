# Исследование разбора библиографических ссылок

НИР «Автоматизированная информационная система оформления библиографических ссылок».

Исследовательский вопрос: насколько точно собственные правила, GROBID, AnyStyle и Qwen3-8B разбирают русскоязычные библиографические ссылки на поля и позволяют оформлять их по ГОСТ Р 7.0.108–2022 для сетевых электронных документов и ГОСТ Р 7.0.5–2008 для остальных ссылок?

## Актуальные данные

[Dataset.xlsx](Dataset.xlsx) — авторская версия от 31.10.2026, скопированная без изменения содержимого.

- 500 ссылок: 398 из журнальных списков литературы, 60 из ВКР, 42 из диссертации.
- DEV — 92, TEST — 408; 203 группы источников без пересечения между частями.
- ГОСТ Р 7.0.108–2022 — 207, ГОСТ Р 7.0.5–2008 — 293. Наличие DOI само по себе не определяет профиль.
- Лист «Датасет»: 27 столбцов, включая 17 эталонных полей, контекст оформления, разбиение и маски. Лист «Источники»: происхождение и существенные оговорки.
- Восемь неоднозначных пар в семи записях; на TEST — семь пар в шести записях. Знаменатель полного совпадения и проверки оформления — 402; на DEV — 91.
- SHA-256: `8aae705b5124e6116ba759fac71d2c731b9f7f480731d6ec4e39187d6ab65179`.

Историческая независимая сверка 100 строк дала 855/880 = 97,16% согласия до согласования. Это показатель той процедуры разметки, а не результат методов и не подтверждение вторым человеком всех последующих исправлений.

## Состояние измерений

Прежние замеры удалены из текущей версии репозитория и сохранены локально отдельно. История Git сохранена. **На актуальном Excel общий итоговый прогон ещё не выполнен; новых F1 и нормативных долей пока нет.** Старые цифры не относятся к этому файлу.

Поддерживаются четыре метода в одном запуске `--method=all`: правила, GROBID 0.9.1 CRF, Qwen3-8B через Ollama и AnyStyle 1.6.0 со стандартной моделью. Все возвращают одну схему из 17 полей. Методы получают только исходную строку; эталон и контекст оформления им не передаются.

## Подготовка и запуск

После установки [GROBID/Ollama](docs/PARSERS.md) и [AnyStyle](docs/ANYSTYLE.md):

```sh
cd backend
./mvnw verify
cd ..
bash scripts/check-research-environment.sh
```

Проверка среды читает Excel и метаданные сервисов, но не запускает извлечение или генерацию. Для нового эксперимента:

```sh
bash scripts/run-dev.sh
```

После полного DEV изучите ошибки, завершите настройку и зафиксируйте протокол:

```sh
cd backend
java -jar target/bibliography-1.0.0.jar \
  --freeze-experiment=../research-runs/dev-four-methods --dataset=../Dataset.xlsx
cd ..
bash scripts/run-final-test.sh
```

TEST использует сохранённый JAR протокола и те же четыре метода. Монитор в другом терминале:

```sh
bash scripts/watch-test-progress.sh "$PWD/research-runs/test-four-methods"
```

Порядок и файлы результата: [эксперимент](docs/EXPERIMENTS.md), [полевые метрики](docs/EVALUATION.md), [форматтер](docs/FORMATTING.md), [проверка ГОСТ и добавлений LLM](docs/QUALITY_REVIEW.md). Доля нормативно корректных ссылок и подтверждённые добавления требуют новых предметных решений по новым ответам; программа не переносит их из старого опыта.

Исправления эталона сделаны после просмотра прежнего TEST. Новый прогон на том же разбиении — повторное сравнение на исправленной версии, а не новая слепая проверка. Настройка методов проводится на DEV; это ограничение необходимо указать в статье.

## Веб-сервис

Приложение: React 19 + TypeScript + Vite, Java 17 + Spring Boot 3.5, Spring Data JPA/Hibernate, PostgreSQL и Flyway. Сервер реализован полностью на Java.

Две вкладки: ручное оформление одной ссылки по рабочему профилю ГОСТ Р 7.0.5–2008 и импорт DOI/ISBN через Crossref/Open Library. Восемь типов источников, включая диссертацию и автореферат. Неполные метаданные отмечаются для исправления; отсутствующие реквизиты не выдумываются. Интерфейс поддерживает обычный режим и `/?embedded=1`.

### Запуск через Docker

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env, например значением из openssl rand -hex 32.
docker compose up --build -d
```

Откройте http://localhost:8080. Сервер автоматически применяет SQL-миграции Flyway и загружает стартовые правила только при их отсутствии.

### Локальная разработка

Нужны JDK 17+, Node.js 24 и PostgreSQL. Maven устанавливать отдельно не требуется: в `backend/` есть Maven Wrapper для macOS/Linux и Windows.

В первом терминале:

```sh
cd backend
export POSTGRES_HOST=localhost POSTGRES_DB=bibliography POSTGRES_USER=bibliography
export POSTGRES_PASSWORD='ваш-пароль'
./mvnw spring-boot:run
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api/` на Java-сервер `127.0.0.1:8000`.

### Проверки

```sh
cd backend
./mvnw verify
```

Тесты используют отдельный настоящий PostgreSQL 17, запускаемый тестовой библиотекой без Docker. При первом запуске Maven загружает зависимости и бинарные файлы PostgreSQL. Для внешней **тестовой** БД задайте `TEST_DATABASE_URL` (JDBC URL), `TEST_DATABASE_USER` и `TEST_DATABASE_PASSWORD`. Не указывайте рабочую БД: тесты меняют тестовые записи.

```sh
cd frontend
npm ci
npm run build
```

Описание [API](docs/API.md), [развёртывания](docs/DEPLOYMENT.md), [возможностей сервиса](docs/FEATURES.md), [фактических проверок](docs/VALIDATION.md).

В веб-интерфейсе импорт eLIBRARY/EDN и произвольного URL, пакетный разбор списков, дополнительные стили, сохранение списков и LDAP пока не реализованы. Исследовательский пакетный разбор доступен через CLI. Проверка исследовательских результатов не является аттестацией всех шаблонов ручной веб-формы.

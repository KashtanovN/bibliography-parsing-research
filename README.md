# Исследование разбора библиографических ссылок

Материалы НИР «Автоматизированная информационная система оформления библиографических ссылок».

Исследовательский вопрос: насколько точно правила, GROBID, AnyStyle и большая языковая модель разбирают русскоязычные библиографические ссылки на поля и позволяют оформлять их по ГОСТ Р 7.0.108–2022 для сетевых электронных документов и ГОСТ Р 7.0.5–2008 для остальных ссылок?

[Датасет — Excel](датасет.xlsx).

## Датасет

В наборе **500 ссылок** с разметкой 17 полей, видом документа, профилем ГОСТ и разбиением по исходным публикациям:

- происхождение строк: 398 из списков литературы журнальных статей, 60 из ВКР и 42 из диссертации;
- части набора: **DEV — 92**, **TEST — 408**; 203 группы источников, группы между частями не пересекаются;
- профили оформления: **ГОСТ Р 7.0.108–2022 — 207**, **ГОСТ Р 7.0.5–2008 — 293**;
- 100 строк проверены вторым разметчиком; согласие до согласования расхождений — **97,16%**;
- в шести записях остаются семь неоднозначных полей: они обрабатываются по [правилам оценки](docs/EVALUATION.md).

Согласие разметчиков характеризует эталонную разметку и не заменяет результаты методов. Вид исходного списка отличается от вида цитируемого документа: например, ссылка на книгу может быть взята из библиографии журнальной статьи.

### Загрузка датасета в Java

```sh
cd backend
./mvnw package
java -jar target/bibliography-1.0.0.jar --check-dataset=../датасет.xlsx
```

Команда читает Excel, проверяет структуру и группы dev/test и выводит сводку. PostgreSQL и веб-сервер не запускаются. Методы разбора получают только ID и исходную строку; эталон и контекст оформления отделены. Подробности — в [описании загрузчика](docs/DATASET.md).

## Сравнение методов

Реализованы четыре метода извлечения: собственные правила, HTTP-адаптер GROBID, Qwen3-8B через Ollama и локальный AnyStyle. Установка AnyStyle описана в [инструкции](docs/ANYSTYLE.md). Запуск отдельных строк и dev/test, настройки сервисов и формат сохранённых ответов описаны в [инструкции методов](docs/PARSERS.md). [Оценщик](docs/EVALUATION.md) считает precision/recall/F1 и полностью правильный разбор. [Общий форматтер](docs/FORMATTING.md) оформляет ответы по двум кратким профилям с одинаковым контекстом. [Проверка качества](docs/QUALITY_REVIEW.md) формирует бланк и автоматически считает нормативную долю и подтверждённые добавления LLM по заполненным решениям; незавершённые проверки отмечаются явно.

Базовый метод — собственные правила и регулярные выражения. С ним сравниваются GROBID, Qwen3-8B и AnyStyle. Конфигурации, модель и её контрольная сумма сохраняются в метаданных прогона.

Метрики: точность, полнота и F1 выделения полей, а также доля полностью корректных ссылок после оформления.

[Сохранение экспериментов](docs/EXPERIMENTS.md): полный журнал сравнения по каждой ссылке, версии и настройки, фиксация протокола после DEV и проверка его неизменности перед TEST.

Прогресс уже запущенного TEST можно смотреть из корня проекта:

```sh
bash scripts/watch-test-progress.sh
```

Монитор обновляется каждые пять секунд. Его закрытие через Ctrl+C не останавливает эксперимент. Для другой папки запуска передайте её первым аргументом.

### Текущие результаты DEV

На 92 строках DEV методы завершили обработку без технических ошибок. Оценка извлечения с общей нормализацией `field-evaluation-v2`:

| Метод | Micro F1 | Полностью правильный разбор |
|---|---:|---:|
| Правила (`rules-v1`) | 0,9685 | 73/91 |
| GROBID 0.9.1, CRF | 0,3839 | 0/91 |
| Qwen3-8B через Ollama | 0,8818 | 16/91 |
| AnyStyle 1.6.0, стандартная модель | 0,4681 | 0/91 |

Знаменатель полного совпадения — 91: R375 исключена из этой метрики из-за неоднозначной роли страниц, остальные её поля оцениваются. В DEV представлены 79 строк из журнальных списков и 13 из ВКР; диссертационная группа находится в TEST.

**Это диагностические результаты DEV. Итоговый TEST завершён 29 октября 2026 года; результаты приведены ниже.** Доля нормативно корректно оформленных ссылок и число подтверждённых необоснованных добавлений LLM пока не определены — требуется предметная сверка. Найденное у Qwen 51 лишнее заполненное поле не означает 51 выдуманный реквизит. Подробности проверок — в [журнале валидации](docs/VALIDATION.md).

## Веб-сервис

Приложение: React 19 + TypeScript + Vite, Java 17 + Spring Boot 3.5, Spring Data JPA/Hibernate, PostgreSQL и Flyway. Сервер реализован полностью на Java.

Две вкладки: ручное оформление одной ссылки по рабочему профилю ГОСТ Р 7.0.5–2008 и импорт DOI/ISBN через Crossref/Open Library. Восемь типов источников, включая диссертацию и автореферат. Неполные метаданные отмечаются для исправления; отсутствующие реквизиты не выдумываются. Интерфейс поддерживает обычный режим и `/?embedded=1`.

### Запуск через Docker

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env, например значением из openssl rand -hex 32.
docker compose up --build -d
```

Откройте http://localhost:8080. Сервер автоматически применяет SQL-миграции Flyway и загружает стартовые правила только при их отсутствии.

### Локальная разработка

Нужны JDK 17+, Node.js 24 и PostgreSQL. Maven устанавливать отдельно не требуется: в `backend/` есть Maven Wrapper для macOS/Linux и Windows.

В первом терминале:

```sh
cd backend
export POSTGRES_HOST=localhost POSTGRES_DB=bibliography POSTGRES_USER=bibliography
export POSTGRES_PASSWORD='ваш-пароль'
./mvnw spring-boot:run
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api/` на Java-сервер `127.0.0.1:8000`.

### Проверки

```sh
cd backend
./mvnw verify
```

Тесты используют отдельный настоящий PostgreSQL 17, запускаемый тестовой библиотекой без Docker. При первом запуске Maven загружает зависимости и бинарные файлы PostgreSQL. Для внешней **тестовой** БД задайте `TEST_DATABASE_URL` (JDBC URL), `TEST_DATABASE_USER` и `TEST_DATABASE_PASSWORD`. Не указывайте рабочую БД: тесты меняют тестовые записи.

```sh
cd frontend
npm ci
npm run build
```

Описание [API](docs/API.md), [развёртывания](docs/DEPLOYMENT.md), [возможностей сервиса](docs/FEATURES.md), [фактических проверок](docs/VALIDATION.md).

В веб-интерфейсе импорт eLIBRARY/EDN и произвольного URL, пакетный разбор списков, дополнительные стили, сохранение списков и LDAP пока не реализованы. Исследовательский пакетный разбор доступен через CLI. Рабочие правила требуют предметной проверки библиотекой.

# Исследование разбора библиографических ссылок

Материалы НИР «Автоматизированная информационная система оформления библиографических ссылок».

Исследовательский вопрос: насколько точно правила, GROBID, AnyStyle и большая языковая модель разбирают русскоязычные библиографические ссылки на поля и позволяют оформлять их по ГОСТ Р 7.0.108–2022 для сетевых электронных документов и ГОСТ Р 7.0.5–2008 для остальных ссылок?

## Датасет

[Скачать Excel с 400 библиографическими ссылками](Датасет_400_библиографических_ссылок.xlsx).

В таблице 400 опубликованных строк из списков литературы 201 статьи восьми журналов портала РУДН. Представлены книги и журнальные статьи. Для каждой записи указаны исходная ссылка, выделенные поля, рабочий вариант оформления, адрес статьи с исходным списком литературы и номер пункта в нём.

- 250 записей с сетевым адресом — рабочий профиль ГОСТ Р 7.0.108–2022.
- 150 остальных записей — рабочий профиль ГОСТ Р 7.0.5–2008.

Исходные строки сохранены без добавления реквизитов; нормализованы только пробелы. Дата обращения из опубликованной строки и дата, отдельно полученная для оформления, находятся в разных столбцах. Разметка и варианты оформления требуют предметной проверки; выполненную проверку следует отмечать в таблице с указанием проверяющего и даты.

## План сравнения

Базовый метод — собственные правила и регулярные выражения. С ним планируется сравнить GROBID, AnyStyle и одну LLM. Конкретные версии инструментов и модель будут зафиксированы до эксперимента.

Метрики: точность, полнота и F1 выделения полей, а также доля полностью корректных ссылок после оформления. В таблице выделены 80 записей для настройки методов и 320 для итоговой проверки. Пункты одного исходного списка не пересекаются между этими частями.

Эксперименты пока не проведены. Набор ограничен книгами и журнальными статьями с различимыми границами реквизитов; результаты на нём нельзя автоматически переносить на все виды библиографических ссылок.

## Онлайн-сервис

Приложение: React 19 + TypeScript + Vite, Java 17 + Spring Boot 3.5, Spring Data JPA/Hibernate, PostgreSQL и Flyway. Сервер реализован полностью на Java.

Две вкладки: ручное оформление одной ссылки по рабочему профилю ГОСТ Р 7.0.5–2008 и импорт DOI/ISBN через Crossref/Open Library. Восемь типов источников, включая диссертацию и автореферат. Неполные метаданные отмечаются для исправления; отсутствующие реквизиты не выдумываются. Интерфейс поддерживает обычный режим и `/?embedded=1`.

### Запуск через Docker

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env, например значением из openssl rand -hex 32.
docker compose up --build -d
```

Откройте http://localhost:8080. Для существующей БД сначала прочитайте [инструкцию переноса](docs/DEPLOYMENT.md#существующая-база). Сервер автоматически применяет SQL-миграции Flyway и загружает стартовые правила только при их отсутствии.

### Локальная разработка

Нужны JDK 17+, Node.js 24 и PostgreSQL. Maven устанавливать отдельно не требуется: в `backend/` есть Maven Wrapper для macOS/Linux и Windows.

В первом терминале:

```sh
cd backend
export POSTGRES_HOST=localhost POSTGRES_DB=bibliography POSTGRES_USER=bibliography
export POSTGRES_PASSWORD='ваш-пароль'
./mvnw spring-boot:run
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api/` на Java-сервер `127.0.0.1:8000`.

### Проверки

```sh
cd backend
./mvnw verify
```

Тесты используют отдельный настоящий PostgreSQL 17, запускаемый тестовой библиотекой без Docker. При первом запуске Maven загружает зависимости и бинарные файлы PostgreSQL. Для внешней **тестовой** БД задайте `TEST_DATABASE_URL` (JDBC URL), `TEST_DATABASE_USER` и `TEST_DATABASE_PASSWORD`. Не указывайте рабочую БД: тесты меняют тестовые записи.

```sh
cd frontend
npm ci
npm run build
```

Описание [API](docs/API.md), [развёртывания](docs/DEPLOYMENT.md), [переноса и границ функциональности](docs/MIGRATION.md), [фактических проверок](docs/VALIDATION.md).

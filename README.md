# Исследование разбора библиографических ссылок

Материалы НИР «Автоматизированная информационная система оформления библиографических ссылок».

Исследовательский вопрос: насколько точно правила, GROBID, AnyStyle и большая языковая модель разбирают русскоязычные библиографические ссылки на поля и позволяют оформлять их по ГОСТ Р 7.0.108–2022 для сетевых электронных документов и ГОСТ Р 7.0.5–2008 для остальных ссылок?

## Датасет

[Скачать Excel с 500 библиографическими ссылками](датасет.xlsx).

В основном наборе 500 опубликованных строк: 398 из списков литературы журнальных статей РУДН, 60 из двух ВКР и 42 из диссертации. Таким образом, 102 строки происходят из ВКР и диссертации. Для каждой записи сохранены исходная ссылка, выделенные поля, вид документа, рабочий вариант оформления, профиль ГОСТ и источник исходного списка.

- 207 записей — профиль ГОСТ Р 7.0.108–2022 для выбранных сетевых электронных документов.
- 293 записи — профиль ГОСТ Р 7.0.5–2008.

Основание выбора профиля указано отдельно: наличие DOI или URL само по себе не определяет профиль. Исходные реквизиты и даты обращения из опубликованных строк отделены от внешнего контекста оформления; происхождение добавленных дат описано на листе «Методика».

Все 500 строк проверены автором исследования. Дополнительно 100 строк проверены Михаилом Саяпиным; 34 решения согласованы 28.10.2026. Согласие до обсуждения составило 855 из 880 сравниваемых пар «ссылка — поле» (97,16%); совместно пустые и отмеченные неопределёнными пары исключены. Это согласие разметки, а не результат работы парсеров.

После согласования семь полей в шести строках остаются неоднозначными. При оценке извлечения эти пары исключаются из знаменателя с отдельным указанием их числа; остальные поля соответствующих ссылок сохраняются в оценке. Ограничения вариантов оформления также отмечены в файле.

Лист «Контроль100» содержит выборку из основных 500 строк, «Исключения» — журнал отклонённых кандидатов, «Методика» — правила формирования и оценки набора. Эти листы не увеличивают число наблюдений.

## План сравнения

Базовый метод — собственные правила и регулярные выражения. С ним планируется сравнить GROBID, AnyStyle и одну LLM. Конкретные версии инструментов и модель будут зафиксированы до эксперимента.

Метрики: точность, полнота и F1 выделения полей, а также доля полностью корректных ссылок после оформления. В таблице выделены 92 записи dev для настройки методов и 408 записей test для итоговой проверки. Пункты одного исходного списка не пересекаются между этими частями. Перед экспериментами необходимо дополнительно проверить совпадения цитируемых произведений между группами.

Эксперименты пока не проведены. Источники набора ограничены журнальными списками РУДН, двумя ВКР и одной диссертацией; результаты нельзя автоматически переносить на все виды русскоязычных библиографических ссылок.

## Онлайн-сервис

Приложение: React 19 + TypeScript + Vite, Java 17 + Spring Boot 3.5, Spring Data JPA/Hibernate, PostgreSQL и Flyway. Сервер реализован полностью на Java.

Две вкладки: ручное оформление одной ссылки по рабочему профилю ГОСТ Р 7.0.5–2008 и импорт DOI/ISBN через Crossref/Open Library. Восемь типов источников, включая диссертацию и автореферат. Неполные метаданные отмечаются для исправления; отсутствующие реквизиты не выдумываются. Интерфейс поддерживает обычный режим и `/?embedded=1`.

### Запуск через Docker

```sh
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env, например значением из openssl rand -hex 32.
docker compose up --build -d
```

Откройте http://localhost:8080. Сервер автоматически применяет SQL-миграции Flyway и загружает стартовые правила только при их отсутствии.

### Локальная разработка

Нужны JDK 17+, Node.js 24 и PostgreSQL. Maven устанавливать отдельно не требуется: в `backend/` есть Maven Wrapper для macOS/Linux и Windows.

В первом терминале:

```sh
cd backend
export POSTGRES_HOST=localhost POSTGRES_DB=bibliography POSTGRES_USER=bibliography
export POSTGRES_PASSWORD='ваш-пароль'
./mvnw spring-boot:run
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api/` на Java-сервер `127.0.0.1:8000`.

### Проверки

```sh
cd backend
./mvnw verify
```

Тесты используют отдельный настоящий PostgreSQL 17, запускаемый тестовой библиотекой без Docker. При первом запуске Maven загружает зависимости и бинарные файлы PostgreSQL. Для внешней **тестовой** БД задайте `TEST_DATABASE_URL` (JDBC URL), `TEST_DATABASE_USER` и `TEST_DATABASE_PASSWORD`. Не указывайте рабочую БД: тесты меняют тестовые записи.

```sh
cd frontend
npm ci
npm run build
```

Описание [API](docs/API.md), [развёртывания](docs/DEPLOYMENT.md), [возможностей сервиса](docs/FEATURES.md), [фактических проверок](docs/VALIDATION.md).

# Оценка качества извлечения

Команда оценивает сохранённые ответы, не вызывает модели и не передаёт им эталон. Правильность оформления по ГОСТ здесь не измеряется: ответы можно передать в [общий форматтер](FORMATTING.md), а нормативную проверку проводят отдельно.

## Запуск

Для нового прогона из `backend` после сборки `./mvnw package`. Для архивного TEST используйте его сохранённый JAR, а не текущую пересборку:

```sh
java -jar target/bibliography-1.0.0.jar \
  --evaluate-run=../research-runs/ИМЯ_ПРОГОНА \
  --dataset=../датасет.xlsx
```

Папка должна содержать `run.json` и файлы ответов перечисленных в нём методов. По умолчанию результат записывается в новую подпапку `evaluation`; существующая не перезаписывается. Другой новый путь задаётся `--evaluation-output=...`.

Программа проверяет SHA-256 Excel, часть набора и размер, уникальность и точный состав ID, сохранение исходных строк и структуру предсказаний. В текущем протоколе `--limit=N` при запуске методов выбирает первые N строк выбранной части; оценщик проверяет именно эту выборку. Частично записанный или относящийся к другому датасету файл не получает правдоподобную оценку.

## Правила подсчёта

Версия нормализации — `field-evaluation-v2`, одинакова для всех методов:

- NFKC, удаление краевых и повторных пробелов;
- в авторах игнорируются пробелы; `;` и запятая между завершёнными инициалами и следующей фамилией с инициалами приводятся к `|`; запятая между фамилией и её инициалами убирается; имена, инициалы, число и порядок авторов сохраняются;
- для DOI убирается префикс DOI/doi.org и игнорируется регистр;
- в ISBN убираются пробелы и дефисы, в диапазонах страниц унифицируется тире;
- календарные даты приводятся к ISO; неверные предсказания не исправляются;
- сетевые варианты книги/журнальной статьи сводятся к соответствующему виду документа;
- прочие регистр, пунктуация, сокращения городов и разрывы внутри слов не исправляются.

Единица оценки — целое значение поля, не отдельные фамилии или токены. Совпавшее непустое значение даёт TP. Пропущенное значение — FN. Лишнее при пустом эталоне — FP. Неверное непустое значение при непустом эталоне даёт одновременно FP и FN. Совместно пустые поля не дают TP. Формулы: precision=TP/(TP+FP), recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN). При нулевом знаменателе показатель неопределён и выводится пустым, а не как 100%.

Micro F1 рассчитан из суммарных TP/FP/FN. Macro F1 — среднее по полям, у которых в оцениваемой выборке есть определённые непустые эталонные значения; знаменатель не зависит от метода. Поля без эталонных значений, в которых появились ложные предсказания, всё равно ухудшают micro F1.

Версия v2 выбрана после анализа DEV и до просмотра TEST: v1 считала запятую в списке авторов фактической ошибкой поля даже при совпавших фамилиях и инициалах. Исходные предсказания не меняются; сохранённые отчёты v1 остаются доступными. Пересчёт v2 выполняется в новых папках одинаково для всех методов.

Семь неопределённых пар в полном наборе исключаются по флагу, а остальные поля этих ссылок продолжают оцениваться. Для доли полностью правильного разбора исключается вся запись с неоднозначностью хотя бы одного поля; числитель и знаменатель выводятся явно. Неуспешный вызов модели учитывается как отсутствие предсказаний и не может считаться полностью правильной записью. Ошибки сервисов не исключаются из отчёта ради улучшения цифр.

Оценщик дополнительно выводит показатели отдельно по исходным спискам: журнальные статьи, ВКР, диссертация. Это группы происхождения строки, а не вид цитируемого документа.

## Файлы результата

- `metrics.json` — все метрики, группировки, ошибки и версия нормализации;
- `records.jsonl` — ответ, ошибка и сравнение всех полей каждой пары «метод — ссылка», включая правильные ответы;
- `comparison_manifest.json` — контрольные суммы ответов/журнала и реализация оценщика;
- `comparison.csv` — сводка методов;
- `field_metrics.csv` — TP/FP/FN, исключения, precision/recall/F1 по каждому полю;
- `differences.csv` — пропущенные, лишние и конфликтующие значения;
- `llm_additions_review.csv` — лишние и конфликтующие заполненные поля Ollama для отдельной предметной сверки;
- `report.md` — краткий отчёт с таблицей F1 по полям.

[Опубликованные результаты TEST четырёх методов](../results/README.md) рассчитаны на 408 ссылках. Диагностические показатели DEV не заменяют TEST. Согласие разметчиков 97,16% не является ни одной из этих метрик и не подставляется вместо результатов методов.

Для фиксации настроек и допуска итогового TEST используйте [протокол сохранения экспериментов](EXPERIMENTS.md).

## Что считать добавлениями LLM

Непустое предсказание при пустом эталоне — лишнее заполненное поле, но ещё не доказанный выдуманный факт. В исходной строке может присутствовать реквизит с другой ролью, либо в эталоне может быть ошибка. Также выдуманное значение может конфликтовать с непустым эталоном, поэтому следует изучить и `differences.csv`.

Колонка `lexical_presence` — только вспомогательный поиск значения в исходном тексте с удалением пунктуации и пробелов. Тип документа и роль страниц являются выводимыми категориями: для них поиск не применяется (`DERIVED_FIELD`). Отсутствие буквального совпадения не доказывает галлюцинацию.

CSV содержит вспомогательные колонки `review_decision` и `review_comment` для заметок. Для статьи отдельно сообщать число лишних заполнений и число подтверждённых необоснованных добавлений. Сам CSV не импортируется в расчёт подтверждённых добавлений: основной заполняемый бланк для автоматического суммирования — `quality/review.json` из команды ниже. Автоматическая программа не подставляет решения проверяющего.

Для полного учёта добавлений (включая совпавшие с ошибочным эталоном ответы), проверки оформленных ссылок и автоматического суммирования решений используйте [общий протокол проверки качества](QUALITY_REVIEW.md). Его бланк `review.json` проверяет все непустые поля LLM и связывает решения с контрольными суммами конкретного прогона.

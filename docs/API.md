# REST API

Базовый путь `/api/`, JSON UTF-8. Публичный генератор не требует авторизации. Ошибки полей: HTTP 400 и объект `fields`; внешние сбои: 503; источник не найден: 404; неподдерживаемый тип публикации: 422; eLIBRARY/EDN: 501; ограничение запросов: 429.

## GET /api/health/

200 `{"status":"ok"}`, если БД доступна и правила загружены; иначе 503.

## GET /api/schema/

Текущая схема форм и форматирования из PostgreSQL: `id`, `label`, `version`, `types`. Доступен только рабочий профиль ГОСТ Р 7.0.5–2008.

## POST /api/format/

```json
{"source_type":"book","fields":{"authors":"Иванов И. И.","title":"Название","city":"Самара","publisher":"Издательство","year":"2026"}}
```

Ответ:

```json
{"formatted":"Иванов И. И. Название. — Самара : Издательство, 2026.","standard":"gost-7-0-5-2008","version":"1.0.0"}
```

Даты в запросах: `YYYY-MM-DD`. Обязательность берётся из схемы. Неизвестные поля и некорректные значения отклоняются. Значения отдельных полей — не более 2000 символов. Сервер не загружает адреса, введённые в поле URL.

## POST /api/import/

```json
{"identifier":"10.1038/nphys1170"}
```

Для ISBN: `{"identifier":"9780140328721"}`. Также принимаются дефисы/префикс ISBN и ссылка doi.org.

Возвращает `source_type`, `fields`, `provider`, `source_url`, `identifier`, `standard`, `version`, `warnings`, `errors`, `formatted`.

При полных данных `formatted` содержит готовую ссылку. При неполных данных ответ всё равно 200 (публикация найдена), `formatted: null`, `errors` указывает поля для исправления. После дополнения сведений вызывайте `/api/format/`.

Метаданные получаются из Crossref по DOI и Open Library по ISBN. Запросы идут только на фиксированные HTTPS-адреса api.crossref.org и openlibrary.org с тайм-аутами, без редиректов и с ограничением размера ответа. Произвольные URL, введённые пользователем, сервер не загружает.

## Общий исследовательский форматтер

`GET /api/formatting-profiles/` возвращает `formatterVersion`, два профиля (`gost-7-0-5-2008`, `gost-7-0-108-2022`) и имена 17 полей.

`POST /api/format-profile/` принимает `profile`, объект `fields` со строками/null и объект `context`. Возвращает результат общего форматтера и замечания о неполноте. Примеры и состав контекста — в [FORMATTING.md](FORMATTING.md#api-сервиса). Неверная схема запроса даёт HTTP 400; неполные допустимые данные — HTTP 200 и `NEEDS_REVIEW`. Эти маршруты отделены от ручной формы `/api/format/`.

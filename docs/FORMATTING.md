# Общий форматтер двух профилей

`SharedCitationFormatter` реализует один зафиксированный краткий затекстовый профиль `shared-short-v1` для ГОСТ Р 7.0.5–2008 и ГОСТ Р 7.0.108–2022. Все методы извлечения проходят через один экземпляр алгоритма. Это ограниченный воспроизводимый профиль, а не реализация всех вариантов стандартов и не библиотечная аттестация.

## Что поступает на вход

1. Предсказанные поля конкретного метода в общей 17-полевой схеме.
2. Общий `Context`: явно выбранный профиль, URL конкретной сетевой версии и календарная дата обращения. Дополнительно можно явно передать название ресурса размещения, примечание о републикации, сохранении пагинации и режиме доступа.

В форматтер не передаются исходная строка, эталонные поля, ожидаемый вариант оформления, источник списка или ID записи. Он не обращается к Crossref, Open Library, GROBID, Ollama или самому URL. Отсутствующие сведения не восстанавливаются по внешним источникам.

Для исследовательского прогона три обязательных элемента контекста берутся из колонок «Применяемый ГОСТ», «URL выбранной сетевой версии», «Дата обращения для оформления» и один раз фиксируются для каждого ID. Ответы моделей в полях URL/ACCESS_DATE не подменяют этот контекст. Наличие DOI не выбирает профиль и не создаёт URL `doi.org`.

## Оформление сохранённого прогона

Для нового прогона из `backend` после `./mvnw package` (архивные прогоны оформляйте их сохранённым JAR):

```sh
java -jar target/bibliography-1.0.0.jar \
  --format-run=../research-runs/ИМЯ_ПРОГОНА \
  --dataset=../датасет.xlsx
```

Модели повторно не запускаются. Проверяются SHA-256 Excel, состав ID, исходные строки, статусы и полнота файлов. Новая папка `formatting` содержит:

- `rules.jsonl`, `grobid.jsonl`, `ollama.jsonl`, `anystyle.jsonl` (для методов прогона): предсказанные поля, одинаковый контекст и результат оформления;
- `formatting.json`: версия форматтера, SHA-256 датасета, контексты, их общая контрольная сумма и количества статусов;
- `references.csv`: строки для сравнения и замечания;
- `preview.md`: первые пять примеров каждого метода.

Существующая папка не перезаписывается. Другой новый путь задаётся `--format-output=...`. Ни Excel, ни исходные ответы методов не изменяются.

## Правила принятого профиля

- Один–три явно названных автора — в заголовке; четыре и более либо неполный список с «и др.» — после косой черты. Инициалы и разделители нормализуются; перечисленные авторы не сокращаются произвольно.
- Составные части отделяются от содержащего издания знаком `//`. Отдельные области разделяются точкой и длинным тире; диапазоны страниц используют `–`.
- Книга, статья журнала, материал сборника, сайт и нормативный документ оформляются по отдельным ветвям. Неизвестный вид не заменяется эталонным. Для диссертации/автореферата 17 полей недостаточно для степени и специальности: результат требует уточнения. Патентный вариант не заявляется.
- Число страниц выводится только вместе с явно заданной ролью. Общий объём оформляется как `200 с.`, диапазон/страница — `С. 10–20`. При неизвестной роли обозначение не угадывается. При явно неподтверждённой/несохранённой пагинации сетевой версии требуется уточнение либо страницы не выводятся согласно переданному флагу.
- В сетевом профиле используются явные URL и дата. Если их нет, они не берутся из предсказаний и не заполняются текущей датой. В принятом варианте дата обращения обязательна; это фиксированный выбор профиля, а не утверждение, что стандарт исключает все варианты с датой публикации.
- Отсутствующие место, издатель и год сетевого объекта опускаются. Известные сокращения города «М.», «СПб.», «Л.» раскрываются в сетевом профиле; произвольные названия организаций не расшифровываются догадкой. Для принятого профиля книги 7.0.5 контролируются место, издатель и год; для статьи — заглавие, издание и год.
- DOI, EDN, ISBN сохраняются в предсказаниях, но не выводятся в этом кратком варианте. Профиль не меняется по наличию идентификатора.
- Сведения о републикации и размещении не выводятся без явного входа. Для специального случая сетевой републикации нужно отдельно подтвердить сохранение пагинации. Контекст трёх колонок Excel не является полной экспертизой сайта.

Варианты пунктуации в эталонных строках могут отличаться от выбранного форматтером варианта. Посимвольное равенство не используется как доказательство соответствия ГОСТ.

## Статусы

`FORMATTED` — алгоритм завершился без обнаруженных недостатков входа в рамках своего профиля. Это не утверждение, что все реквизиты верны или что ссылка подтверждена библиографом. Метод мог уверенно предсказать неверные данные.

`NEEDS_REVIEW` — сохранена доступная часть строки и конкретные замечания: нет заглавия/издания, неизвестен вид, не определена роль страниц, недостаточно контекста и т. п. Пропущенные данные не восполняются эталоном.

`SKIPPED_SOURCE_ERROR` / `SKIPPED_SOURCE_EMPTY` — ссылка не формируется из эталона вместо ответа неуспешного метода.

Доля нормативно корректных оформленных ссылок рассчитывается командой `--quality-run` по [решениям предметной проверки](QUALITY_REVIEW.md). Нужно проверить состав и достоверность реквизитов, специальные случаи размещения и требования профиля; счётчик FORMATTED не заменяет такую оценку. Для нового пустого бланка доля не определена до заполнения решений; [завершённая проверка TEST](../results/review-20261029/README.md) опубликована. Семь неоднозначных эталонных пар продолжают учитываться по отдельному протоколу.

## API сервиса

`GET /api/formatting-profiles/` возвращает два профиля и имена 17 полей.

`POST /api/format-profile/` использует тот же класс, что CLI. Пример:

```json
{
  "profile": "gost-7-0-108-2022",
  "fields": {
    "DOCUMENT_TYPE": "Журнальная статья",
    "AUTHORS": "Иванов И. И.",
    "TITLE": "Название статьи",
    "CONTAINER_TITLE": "Журнал",
    "YEAR": "2024",
    "PAGES": "10–20",
    "PAGE_MEANING": "Указатель страниц"
  },
  "context": {
    "url": "https://example.org/article",
    "accessDate": "2026-10-27"
  }
}
```

Для 7.0.5: `profile: "gost-7-0-5-2008"`, `context: {}`. Значения полей — строки или null. Дополнительные ключи контекста: `hostingResource`, `republicationNote`, `paginationPreserved` (boolean/null), `accessNote`. Эталонные данные в контексте не принимаются. Синтаксически неверный запрос получает HTTP 400; корректный запрос с неполными сведениями — HTTP 200 и NEEDS_REVIEW.

Существующий `/api/format/` и ручная веб-форма используют прежний настраиваемый профиль 7.0.5. Новый общий профиль доступен через CLI и отдельный API; переключатель 7.0.108 в веб-форму на этом этапе не добавлялся.

## Нормативные основания и границы

Правила согласованы с основными положениями [ГОСТ Р 7.0.5–2008](https://library.istu.edu/content/gost-r-7-0-5-2008.pdf), пп. 4.5, 4.9, 4.10, раздел 7, и текстом [ГОСТ Р 7.0.108–2022](https://dalgau.ru/upload/iblock/fee/0gss1spev5ejuzsl0svcjkpeijcy3hb6/GOST-R-7.0.108_2022-Bibliograficheskie-ssylki-na-elektronnye-dokumenty.pdf), пп. 4.3–4.4, 5.1–5.3, 6.1–6.3. Выбран краткий воспроизводимый вариант; специальные случаи не объявляются автоматически покрытыми. Сведения о выбранной версии и режиме доступа должен подтвердить пользователь/проверяющий.

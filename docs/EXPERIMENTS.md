# Запуск и сохранение эксперимента

Текущая программа запускает четыре метода через `--method=all`: правила, GROBID, Qwen3-8B и AnyStyle. Настройка выполняется на DEV, затем фиксируется протокол и обрабатывается полный TEST. [Опубликованные результаты](../results/README.md) уже получены; команды ниже предназначены для нового эксперимента.

## Среда и полный DEV

Установите [AnyStyle](ANYSTYLE.md), запустите [GROBID и Ollama](PARSERS.md). Из `backend`:

```sh
./mvnw package
java -jar target/bibliography-1.0.0.jar \
  --parse-dataset=../датасет.xlsx --method=all --split=dev \
  --output=../research-runs/dev-four-methods

java -jar target/bibliography-1.0.0.jar \
  --evaluate-run=../research-runs/dev-four-methods --dataset=../датасет.xlsx
```

Имя выходной папки должно быть новым. Для фиксации нужен полный DEV, без `--limit`; короткая проверка на трёх строках не подходит.

## Фиксация протокола

```sh
java -jar target/bibliography-1.0.0.jar \
  --freeze-experiment=../research-runs/dev-four-methods \
  --dataset=../датасет.xlsx
```

В `frozen-protocol/` сохраняются `protocol.json`, его SHA-256, критерии оценки/оформления/проверки и исполняемый `application.jar`. Фиксируются версия данных, 92 DEV / 408 TEST, конфигурации всех методов, модель/digest Qwen, версии сервисов, модель и среда AnyStyle, промпт, тайм-аут и снимок кода.

После фиксации используйте сохранённый JAR. Пересборка с изменённым кодом не подменяет зафиксированный эксперимент. Метаданные сервисов и настройки перед TEST должны совпасть. Изменение адресов допускается при сохранении конфигураций и версий. За стабильностью работающих сервисов во время опыта следит исследователь.

## Полный TEST

Из `backend`:

```sh
java -jar ../research-runs/dev-four-methods/frozen-protocol/application.jar \
  --parse-dataset=../датасет.xlsx --method=all --split=test \
  --protocol=../research-runs/dev-four-methods/frozen-protocol \
  --output=../research-runs/test-four-methods
```

TEST не допускает `--limit`. Папки не перезаписываются. Ошибки методов сохраняются и входят в оценку; не выбирайте удачный повтор вместо первого результата.

Для автоматического выполнения TEST → оценка → оформление → бланк проверки из корня проекта:

```sh
bash scripts/run-final-test.sh \
  "$PWD/research-runs/test-four-methods" \
  "$PWD/research-runs/dev-four-methods/frozen-protocol"
```

Скрипт не собирает приложение заново и не заполняет предметные решения автоматически. На macOS он удерживает компьютер от сна; крышка должна оставаться открытой. Код 3 извлечения означает завершение с сохранёнными ошибками методов и допускается к последующей оценке. Повторный запуск в существующую папку отклоняется.

## Прогресс

```sh
bash scripts/watch-test-progress.sh "$PWD/research-runs/test-four-methods"
```

Монитор читает методы и объём из прогона, показывает строки, ERROR/EMPTY и ориентир остатка Qwen. Он поддерживает и архивные прогоны с другим составом методов. Второй аргумент `--once` выводит один снимок. Ctrl+C закрывает только монитор. Процент относится к числу вызовов, а не к доле времени. Файлы `.pipeline-status`, `.pipeline.pid`, `.java.pid`, `.started` относятся к автоматическому запуску.

## Сохранённые файлы и пересчёт

- `run.json`: данные, DEV/TEST, параметры запуска, время, среда, настройки методов, SHA реализации и протокола.
- Файлы `rules.jsonl`, `grobid.jsonl`, `ollama.jsonl`, `anystyle.jsonl`: исходная ссылка, предсказанные поля, полный ответ метода, статус/ошибка и длительность. Строки записываются по мере обработки.
- `summary.json`: SUCCESS/EMPTY/ERROR каждого метода.
- `evaluation/records.jsonl`: все пары «метод — ссылка», сравнения 17 полей, TP/FP/FN и признак полного совпадения. `comparison_manifest.json` связывает расчёт с исходными файлами.
- `formatting/`: готовые ссылки и одинаковый контекст каждого ID.
- `quality/`: бланк решений и показатели проверки. Первоначально пустой бланк не означает отсутствие ошибок.

Для оценки своего нового TEST используйте его собственный JAR:

```sh
java -jar ../research-runs/test-four-methods/protocol/application.jar \
  --evaluate-run=../research-runs/test-four-methods --dataset=../датасет.xlsx
```

Аналогично работают `--format-run` и `--quality-run`; существующие подпапки не перезаписываются, для повторного расчёта задавайте новый выходной путь. Процедура предметной проверки — в [QUALITY_REVIEW.md](QUALITY_REVIEW.md).

## Опубликованные архивы

[Навигация по результатам](../results/README.md) отделяет исходные прогоны, четырёхметодное сравнение и итоговую проверку. Три исходных метода и AnyStyle в опубликованных данных получены двумя зафиксированными прогонами; их ответы объединены без повторных вызовов. Это происхождение сохраняется в run.json и протоколах. Копии критериев и JAR внутри архивов описывают свой этап и не меняются вместе с текущей документацией.
